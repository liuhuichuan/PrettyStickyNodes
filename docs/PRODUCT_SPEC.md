## 1. 产品目标

PrettyStickyNodes 是一个常驻桌面的轻量 Todo 便签。用户开机后可以快速记录办公事项，按执行顺序排列，完成后得到短暂反馈并移除事项。窗口小、圆角、宝石蓝、有轻微 3D 深度；内容优先，避免无实际意义的装饰。

MVP 必须覆盖：启动显示、添加、编辑、完成、撤销、删除、手动排序、长列表滚动、多清单切换、关闭与重新打开、自动保存与恢复。

## 2. 设计与页面对应

Figma 文件中的页面是静态状态稿，开发实现需复用主界面的视觉语言：

| 页面 | 用途 |
|---|---|
| `01 · 主界面` | 默认窗口、4 条事项、固定 Add task |
| `02 · 完成与撤销` | 勾选反馈、事项移除、5 秒 Undo |
| `03 · 添加事项` | 底部原地输入、Enter 添加、Esc 取消 |
| `04 · 列表滚动` | 超过可视区域后的内部滚动 |
| `05 · 编辑事项` | 双击事项后的原位编辑 |
| `06 · 手动排序` | 默认、悬停手柄、拖动中和一次性提示 |
| `07 · 多清单与项目` | Daily、临时项目、右侧索引标签、新建清单 |

Figma 中的中文说明文字属于设计注释，不显示在应用窗口内。应用内标题和事项示例使用英文；实际事项由用户输入，允许 Unicode。`07 · 多清单与项目` 中的右侧标签属于窗口内导航，不是窗口外背景；开发时应保持当前清单与标题、列表、添加入口同步。

## 3. 窗口与视觉规范

- 默认窗口为紧凑便签尺寸，建议主面板设计区域约 `400 x 390` 逻辑像素（不含右侧标签外延），允许用户调整大小。
- 右侧索引标签在主面板外延伸约 98 px，属于同一个原生窗口；总窗口边界须包含标签和阴影，禁止被主面板圆角裁剪。主面板尺寸保持原比例，透明空隙不作为拖拽或点击区域。
- 外层圆角约 24 px；窗口自身必须裁剪内容，不能露出白色方角。
- 标题栏使用宝石蓝渐变和轻微高光/阴影，正文使用浅蓝渐变；不要把整个窗口填成单一颜色。
- Daily 的标题为 `Today’s focus`；项目标题为清单名称；新建状态为 `New list`。不显示大日期、进度统计或额外装饰标题。
- 右上角显示清晰的白色 `X` 关闭按钮，按钮区域建议不小于 32 x 32 px。
- 关闭按钮不使用与背景不一致的独立色块；不放 macOS 三色圆点、无语义横杠或装饰性按钮。
- 事项行包含：完成控件、文本、悬停时才出现的六点拖动手柄。默认不显示数字、优先级颜色或 `Next` 标签。
- 正文、按钮和提示文字需满足 WCAG AA 对比度；键盘焦点必须有可见焦点环。

## 4. 数据模型与持久化

```text
TodoItem {
  id: string (稳定且唯一)
  text: string
  completed: boolean        // 完成反馈期间可短暂为 true
  order: integer            // 越小越靠前
  createdAt: timestamp
  updatedAt: timestamp
}

AppState {
  schemaVersion: 2
  window: { x?: integer, y?: integer, width: integer, height: integer }
  firstRunSortHintDismissed: boolean
  launchAtLogin: boolean
  activeListId: string
  lists: TodoList[]
}

TodoList {
  id: string (稳定且唯一)
  name: string
  kind: "daily" | "project"
  archived: boolean
  items: TodoItem[]
  scrollOffset: integer
  createdAt: timestamp
  updatedAt: timestamp
}
```

- 每次添加、编辑、完成、删除、撤销、排序后立即保存，采用原子写入，避免进程异常造成半文件。
- 启动时读取最后一次有效状态；文件损坏时保留损坏文件副本并加载空列表，同时给出可诊断日志。
- `order` 在所属清单内表示用户执行顺序。拖动后重新编号，不能按文本、创建时间或完成状态自动重排。
- MVP 可使用本地 JSON/SQLite；不需要账号、云同步或网络服务。
- `Daily` 是不可删除、不可归档的固定清单；临时项目清单可以重命名和归档。
- 每个清单独立保存事项、执行顺序和滚动位置；切换清单不复制或合并事项。
- `activeListId` 决定当前窗口标题、当前列表内容和底部添加入口的归属。

### 4.1 从单清单数据迁移

读取旧版顶层 `items` 时，将原事项的 ID、文本和顺序原样迁入唯一的 Daily 清单，并设 activeListId 为 Daily；新模型不再保留顶层 items。迁移前备份原数据，完整写入 schemaVersion=2 后才视为成功。迁移失败保留原文件并提示错误，不以空数据覆盖；重复启动不得重复导入。清单操作与事项操作同样需要原子持久化。

## 5. 交互规格

### 5.1 启动、关闭和托盘

1. 开机自启默认开启；用户可在托盘菜单关闭。
2. 启动后显示便签窗口并恢复上次内容、顺序和窗口位置/尺寸；恢复上次活动清单，无有效活动清单时回到 Daily。
3. 点击右上角 `X`：隐藏窗口到系统托盘，不清空事项、不终止后台进程。
4. 托盘菜单至少包含：`Show note`、`Launch at login`（带勾选状态）、`Archived lists…`、`Exit`。
5. `Exit` 才真正结束进程；下次启动仍从最后一次保存状态恢复。
6. 托盘图标、菜单和关闭行为必须符合 Windows 10/11 习惯；关闭后应用仍可被快捷方式或托盘重新显示。

### 5.2 多清单与项目标签

1. 首次使用默认打开 `Daily` 清单；第一版使用一个窗口承载多个清单，不创建多个便签窗口。
2. 清单以窗口右侧的垂直索引标签显示，类似书页标签；标签不占用正文列表高度。
3. 当前清单标签使用浅色高亮并与窗口正文视觉相连；其他标签使用较深的蓝色退后显示。
4. 标签名称使用短横向文本；过长名称截断显示，悬停时显示完整名称。最多直接展示 3 个清单标签（包含 Daily 和当前项目）；超出时提供 `More lists…` 菜单选择其他清单。`+ New list` 仅负责创建，不能兼作清单切换入口。
5. 切换清单后同步更新：窗口标题、当前事项列表、当前清单名称、`Add task to <list>` 文案和滚动位置。
6. 新增事项只能写入当前清单；编辑、完成、删除、排序也只作用于当前清单。
7. 点击 `+ New list` 进入新建状态；输入项目名称后按 `Enter` 或 `Create` 创建并自动切换到新清单；`Esc` 或 `Cancel` 返回原清单，取消不创建数据。新建态隐藏添加事项入口。
8. 清单名称去除首尾空白后不能为空；名称最多 32 个 Unicode 字符；活动清单名称经首尾去空白及不区分大小写比较后不得重复，报错保留输入。用户可输入中文或 Emoji。
9. 临时项目清单支持右键菜单 `Rename` 和 `Archive`；`Daily` 不提供重命名或归档。归档后从标签区移除，本地内容保留；归档当前清单时切回 Daily。托盘提供 `Archived lists…` 入口及 `Restore` 操作；恢复时如名称冲突，要求先输入不重复名称，不覆盖已有清单。
10. 切换清单时若存在未提交的添加/编辑输入：先保存当前输入；若当前输入为空则取消；不得把文本写入目标清单。
11. 切换期间先处理原清单输入，再更新 activeListId；拖动中禁止切换，先释放或 Esc 取消。输入法候选确认的 Enter 不得触发创建或保存。
12. 完成/删除撤销按清单隔离，每个清单仅保留最近一次操作，切换不重置 5 秒倒计时。切回后仅在仍有效时显示 Undo，恢复到原清单；撤销记录不跨进程保存。
13. 窗口关闭、程序退出和系统关机前保存当前清单 ID，以及每个清单的事项、顺序和滚动位置。

### 5.3 添加事项

1. 点击固定在列表底部的 `+ Add task`，底部入口切换为单行输入框。
2. 输入框获得焦点；`Enter` 保存，`Esc` 取消。
3. 去除首尾空白后文本为空：不创建事项并退出输入态（或恢复原入口）。
4. 保存后新事项追加到列表底部，成为最低执行顺序，立即持久化。
5. 输入过长时允许换行或省略显示，但不能遮挡完成控件和滚动区域；建议单项文本长度上限 500 个 Unicode 字符。
6. 添加态不改变标题栏和窗口外观。

### 5.4 编辑事项

1. 双击事项文本进入原位编辑；完成控件和其他行保持原位。
2. 使用蓝色细边框输入框表示编辑中，默认全选或将光标置于双击位置，二者选其一并保持一致。
3. `Enter` 保存；`Esc` 恢复原文本并退出；点击输入框外保存并退出。
4. 去除首尾空白后为空：恢复原文本，不允许把事项保存为空。
5. 编辑期间不能因点击完成控件或拖动手柄而误触发完成/排序。

### 5.5 完成、反馈与撤销

1. 点击事项左侧完成控件后立即显示勾选和删除线反馈，反馈持续约 250 ms。
2. 反馈期间保留当前行，随后移除该事项，其余事项向上移动。
3. 底部显示 `Task completed` 与 `Undo`，撤销入口保留 5 秒；计时结束后自动消失。
4. 点击 `Undo`：恢复该事项原文本、原顺序和未完成状态；只撤销当前清单最近一次完成/删除操作，两者共用一个撤销槽。
5. 完成事项移除后不能再通过普通列表编辑；若用户要永久删除未完成事项，使用右键菜单或键盘删除命令。
6. 完成、移除和撤销均立即保存。

### 5.6 删除事项

1. 对未完成事项提供右键菜单 `Delete`，并支持键盘 `Delete`（事项获得焦点时）。
2. 删除前不强制弹模态确认；删除后提供短暂 `Undo`（建议 5 秒），避免误删。
3. 删除不改变其他事项的相对顺序；重新编号并保存。
4. 删除中的编辑态先退出编辑，再执行删除，不能留下悬空输入框。

### 5.7 手动排序

1. 列表由上至下表达执行顺序；这是执行顺序，不代表系统自动计算的优先级。
2. 默认隐藏六点手柄；鼠标悬停事项行时显示手柄，行背景轻微高亮。
3. 从手柄按下并拖动开始排序；拖动对象单独浮起，其他行让出连续间隙。
4. 蓝色插入线显示释放位置，不能穿过文字或完成控件。
5. 释放后保存新顺序；按 `Esc` 取消本次拖动并恢复原顺序。
6. 第一次使用排序时显示一次 `Drag tasks to reorder` / `Got it` 提示。提示在点击 `Got it` 或完成一次排序后消失，并持久化 `firstRunSortHintDismissed=true`。
7. 排序不得触发编辑、完成或删除；拖动手柄的有效触控/鼠标区域建议不小于 24 x 24 px。

### 5.8 列表滚动与空状态

1. 标题栏和底部 `+ Add task` 固定，只有事项列表区域滚动。
2. 少于等于可视行数时不显示滚动条；超出时显示 Windows 原生或同风格的细滚动条。
3. 滚轮、触控板、拖动滚动条和键盘方向键均可滚动列表。
4. 空列表显示明确的空状态和 `+ Add task`，用户无需猜测添加位置。
5. 滚动时不能带动标题栏、关闭按钮或底部添加入口。

## 6. 键盘与可访问性

- `Tab` 顺序：关闭按钮 -> 清单标签及新建/更多入口 -> 列表事项完成控件/文本 -> Add task -> 托盘相关不可见控件不进入窗口 Tab 顺序。
- 标签可使用键盘聚焦，Enter/Space 激活；Shift+F10 打开项目菜单。
- `Enter`：添加态保存、编辑态保存、新建清单提交。
- `Esc`：取消添加、取消编辑、取消排序。
- `Space`：焦点在完成控件时切换完成状态。
- `Delete`：焦点在事项时删除（可撤销）。
- 任何可点击控件必须有可读名称；完成控件应包含事项文本的辅助标签。
- 支持 Windows 高对比度和系统缩放；文本放大后不得截断关键操作。
- 动画提供 reduced-motion 兼容：关闭动画时仍保留状态变化和撤销能力。

## 7. 错误与边界规则

- 保存失败：保留内存状态，显示非阻塞错误提示并重试；退出前再次尝试保存。
- 启动数据无法解析：加载空状态并写日志，不覆盖原文件。
- 同时触发多个操作时以当前明确手势为准；保存操作串行化，不能发生旧状态覆盖新状态。
- 文本包含换行、Emoji、中文、RTL 字符或超长单词时，布局不能溢出窗口；必要时换行并限制最大行高。
- 窗口被拖到屏幕外或分辨率变化后，启动时将窗口裁回可见工作区。
- 系统进入睡眠、注销、关机时，先执行一次同步保存。

## 8. 测试项与验收标准

### 8.1 单元测试

- 清单隔离：在 Daily 和项目清单分别添加、编辑、完成、删除、排序，另一清单数据不发生变化。
- 清单切换：切换后 `activeListId`、标题、列表、添加入口和滚动位置一致；切换回来状态恢复。
- 新建清单：Enter 创建并切换，Esc 取消，空名称不创建，名称规范化和长度限制正确。
- 清单生命周期：Daily 不能归档；项目清单可重命名、归档和恢复；归档不丢失事项。

- `order` 排序：追加、移动到首位/末位/中间、取消拖动后顺序不变。
- 文本规范化：首尾空白、空字符串、Unicode、Emoji、换行和长度上限。
- 完成状态机：未完成 -> 反馈中 -> 已移除；撤销窗口 5 秒内可恢复，超时不可恢复。
- 删除撤销：删除后恢复原文本和原位置；多次删除只允许按产品定义撤销最近一次。
- 一次性提示：首次显示，点击 `Got it` 或成功排序后持久化，重启后不再显示。
- 原子保存：写入失败不会产生半截状态文件；旧有效状态仍可读取。
- 窗口边界：窗口位置裁回可见工作区。

### 8.2 集成测试

- 新增事项后重启，事项文本和顺序保持不变。
- 在 Daily 创建 `Release` 清单并添加事项，切换来回后确认两份清单完全隔离。
- 创建、重命名、归档项目清单，重启后当前清单和归档状态保持不变。
- 在添加/编辑未提交时切换标签，确认输入按规则保存或取消，绝不串到另一清单。
- 编辑后重启，保存后的文本恢复；Esc 和空白编辑不改变原文本。
- 完成事项后，250 ms 反馈、行移除和 5 秒 Undo 顺序正确。
- 删除、撤销、排序混合操作不会丢失或重复事项。
- 关闭窗口后从托盘 `Show note` 重新显示；`Exit` 后进程确实结束。
- 开机自启开关在托盘菜单中可读、可切换，设置重启后保持。
- 5 条、20 条、100 条事项下列表滚动正常，标题栏和 Add task 固定。
- 在编辑态点击完成、拖动手柄、关闭窗口时行为符合定义，不产生重复提交。

### 8.3 UI/视觉验收

- 与 Figma `01 · 主界面` 对比：窗口尺寸比例、圆角、宝石蓝标题栏、浅蓝正文、白色 X、固定 Add task 一致。
- 与 Figma `02 · 完成与撤销` 对比：勾选反馈、删除线、事项上移、Undo 文案和位置一致。
- 与 Figma `03 · 添加事项` 对比：原地输入、Enter/Esc 操作明确，输入框不覆盖关闭按钮。
- 与 Figma `04 · 列表滚动` 对比：仅列表滚动，标题栏和 Add task 固定。
- 与 Figma `05 · 编辑事项` 对比：蓝色细边框、原位编辑、Enter/Esc 提示一致。
- 与 Figma `06 · 手动排序` 对比：默认/悬停/拖动三个状态可辨认；插入线不穿过文本；一次性提示只出现一次。
- 与 Figma `07 · 多清单与项目` 对比：右侧标签不挤占正文高度；当前标签、窗口标题、事项列表和 Add task 归属一致；新建清单状态可辨认。
- 检查 100%、125%、150% Windows 缩放和高对比度模式。
- 检查英文界面长文本、中文文本、Emoji、两行文本无裁切和重叠。

### 8.4 手工回归清单

1. 使用隔离的测试数据目录启动应用，确认 Daily 空状态和 Add task 可见，不删除真实用户数据。
2. 添加 4 条事项，关闭窗口，托盘重新打开，确认内容和顺序。
3. 双击第二条编辑，分别验证 Enter、Esc、点击外部三种路径。
4. 完成第一条，等待反馈、移除、Undo，分别在 4 秒和 6 秒点击撤销。
5. 右键删除一条，验证 Undo 和顺序恢复。
6. 添加到超过可视行数，滚动到底部，确认标题栏和 Add task 不动。
7. 创建一个临时项目清单，切换标签并添加事项；切回 Daily，确认事项没有混入。
8. 重命名并归档临时项目，重新启动应用，确认 Daily 保留、项目可恢复。
9. 第一次拖动排序，验证提示；再次拖动，确认提示不再出现；Esc 取消拖动。
10. 切换开机自启，重启应用验证；点击 X 后从托盘恢复；点击 Exit 验证进程退出。
11. 断开/模拟保存失败，确认错误提示、重试和数据不被清空。

## 10. 开发完成定义

当核心交互、持久化、托盘行为和上述自动化/手工测试通过，并且在 Windows 10/11 的 100%/125%/150% 缩放下完成视觉验收，MVP 才算完成。Figma 静态稿用于视觉和状态对照；拖动、编辑、撤销、托盘和保存必须在产品中实现为真实交互。
